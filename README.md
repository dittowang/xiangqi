# 象棋 · 千里江山

A 3D Chinese chess (xiangqi) game in the browser, rendered as **工筆重彩** — gongbi
heavy-colour painting — with every piece a fully modelled Han or Chu soldier
rather than a disc with a character on it.

```bash
npm install
npm run dev
```

That is the whole setup. There is nothing to download and nothing to configure.

---

## Zero external assets

Nothing in this repository was downloaded, and `three` is the only runtime
dependency. Every asset you see or hear is generated by code in this tree:

| | How it is made |
|---|---|
| Meshes | Parametric geometry — lathes, beveled extrusions, hand-authored `BufferGeometry`. `src/characters/parts/` |
| Textures | Canvas 2D and shader noise, all seeded. `src/render/textures.ts`, `src/core/noise.ts` |
| Characters | 60 hand-authored 篆書 seal-script glyphs as stroke centrelines. No fonts. `src/ui/glyphs.ts` |
| Animation | `KeyframeTrack` data emitted in code — 84 clips, 1,596 tracks, 52,136 keyframes. `src/anim/clips.ts` |
| Audio | Web Audio synthesis — modal resonator banks, Karplus-Strong, membrane models. No samples. `src/ui/audio.ts` |
| Chess engine | Written from scratch: rules, search, evaluation, opening book. No library, no book file. `src/engine/` |

## Architecture

`ARCHITECTURE.md` is the full brief: directory ownership, the permitted import
graph, the render pass order, the performance budget, and per-subsystem done
criteria. The short version:

- `src/core/` is a frozen contract layer — board vocabulary, the mineral-pigment
  palette, seeded RNG, the event bus, and the interfaces every subsystem
  implements. Everything else depends on it and it depends on nothing.
- The engine is **isomorphic**: the same code runs on the main thread and inside
  the Web Worker. Hovering a piece computes its legal destinations synchronously,
  with no round trip; only the search runs in the worker.
- Rendering is one pass order, fixed: depth/normal prepass → inverted-hull
  outlines → quantised surface → Sobel interior lines → grade. There is exactly
  one draw call site in the frame loop.
- Everything procedural draws from `seedFor(...)`. No `Math.random()`, and no
  `performance.now()` in an update path — the capture harness owns the clock, so
  a captured frame is a reproducible measurement rather than a snapshot.

## The rules

Full xiangqi, including the parts most implementations get wrong:

- Flying general (對面笑) — enforced as ordinary legality, because `isAttacked`
  models the general as a vertical slider, so no special case is needed.
- Blocked horse leg 蹩馬腿 and blocked elephant eye 塞象眼.
- Elephants confined to their own bank; advisors and generals to the palace.
- Cannons capture only over **exactly one** screen.
- Soldiers gain sideways movement only after crossing the river, never backward.
- **Stalemate is a loss for the stalemated side** — the opposite of Western chess.
- **Perpetual check is a loss for the checking side.** Mutual perpetual check is
  a draw.
- Sixty full moves with no capture is a draw; bare general against bare general
  is a draw.
- Perpetual chase (長捉) is detected to a documented approximation —
  `src/engine/rules.ts` states exactly what it catches and what it misses.

Verified by 176 tests. Perft from the start position matches the published
values — 44 / 1920 / 79666 / 3290240 — and five further fixtures are
cross-checked against a deliberately naive reference generator written in the
test file, comparing full legal move **sets** rather than counts, which is what
catches two errors cancelling out. 200 self-play games produced 5,169 engine
moves, every one validated legal against that reference.

## The capture harness

Every visual claim in this project is checked against a real captured frame, not
against an assumption about what the code does.

```bash
npm run capture -- stills
npm run capture -- silhouettes    # flat black units, for readability review
npm run capture -- motion         # frame sequences composed into contact sheets
```

The harness drives the shipped build in real Chromium through `window.__XQ`
(`src/core/testapi.ts`): it pauses the clock, steps by an exact dt, seeks a
capture animation to a normalised time, isolates a single unit, and strips
materials to silhouette. It fails loudly on a page error and on a blank frame,
because a harness that quietly returns black is worse than no harness.

**If you are capturing frames for review, force the quality tier first:**

```js
window.__XQ.setQuality('ultra');
```

The governor probes the GPU and maps a software rasteriser to the `low` tier.
That is right for playing and wrong for judging.

## Status

This is an honest account rather than a summary.

**Working.** The game plays: full rules, three difficulty tiers, spring-damped
orbit camera, a board with real depth, 32 procedurally generated figures with
skinned animation, the three-beat capture choreography, pigment dispersal, and
synthesised audio. The engine reaches depth 7–8 on its hard tier in 2.6 s at
77–95k nodes/second.

**Measured, not asserted.** Foot contact-point slide over six squares of travel
is 0.00000000. Wheel travel 4.587023606 world units against wheel arc
4.587023606 — zero slip. Hand-to-haft separation 0.000000 across every state.
Analytic IK positional error 0.0 over 3,800 targets. Every triangle in the cast
and the board passes a winding, closure and signed-volume audit.

Review mode was driven in a real browser rather than inspected: the sweep grades
every ply with a quality, a tone and a full principal variation, the cursor walk
produces exact and reversible board states, and exit restores the position it
started from. The whole application occupies **3 DOM nodes** — the move record,
the evaluation bleed and the captured figures are all painted into the scene, so
"never a default HTML widget" is a measurement here and not an intention.

**Not there yet.** The gongbi surface treatment is the least finished part of the
project. N·L is bimodal under the current light rig, so the mid bands of each
four-band ramp are barely selected and material classes do not yet differentiate
as they should — lacquer, cloth and timber read too much alike. The backdrop
reads as flat cut paper, cast shadows dominate the figures and alias badly, and
only four of the seven unit types are identifiable by silhouette alone. No frame
has been judged in motion by a critic, and nothing has been
run on the target hardware: all performance figures here were taken under
software rasterisation, so the locked-60 claim is an architectural argument —
draw calls, triangle counts, allocation-free update paths — not a measurement.
